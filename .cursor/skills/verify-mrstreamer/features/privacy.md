# Product-use and reliability statistics

## How to get to it

Open Settings > General > Privacy. Share basic usage statistics is on by default. Turn it off with the checkbox; the helper must match the delivered catalogue in `docs/telemetry.md`, and Privacy policy opens the canonical policy in the system browser. No first-use notice or upgrade prompt is shown. Settings > About retains its Privacy link.

## Driving the built app

After `pnpm build`, run `xvfb-run -a node apps/desktop/test/e2e/analytics-app.ts` on headless Linux. The helper owns an isolated profile, loopback capture endpoint and debugging ports. It drives the Settings checkbox with pointer input, observes ordinary preferences and actual capture payloads, restarts the same isolated profile, and retains screenshots, payloads, instance identity and cleanup proof under `.local/verification/analytics-*`. It uses fake provider/TMDB boundaries and a loopback release feed, with automatic updates off. Product mutations use pointer/keyboard input. Named pointer targets are resolved again after scrolling and hover, require settled geometry and a matching hit, and retain the actual mousedown target in `proof.json`. It does not advance the clock; UTC rollover of `app_active_day` is covered by the focused owner tests in `apps/desktop/test/analytics.test.ts`. Production transport is impossible for this isolated profile, even if a release bundle contains production configuration.

Require a checked default and exactly one installation_observed plus one app_active_day. Every captured raw body must equal its schema-reconstructed allowlist; the proof records the exact property-key set per event name. Drive EPG expansion, a committed favourite and a nonempty search, each with its durable fixed counter. Open the continuous fake broadcast from search; require a persisted admitted journal and no playback HTTP event until its end. Measure at least 34 seconds in Watch, a Home preview of at least 12 seconds with no summary, and return to Watch under the same run. Opening provider VOD emits exactly one ended live summary with at least 32 seconds and no more than observed wall time minus preview plus three seconds. Pause, paused seek and resume preserve the VOD journal UUID and emit no early summary. Watch offline ends that VOD with one summary and admits the next. Completed/cancelled/failed downloads retain direct outcomes. Failed title open reports exactly one typed incident and no summary for that attempt. Exercise all ten screen entries, autoplay-next, successful/failed manual update checks, update seen/dismissed, source added/refreshed and an actual owned renderer crash/reload. Quit/restart seals the final usage fragment while preserving identity; every raw HTTP body must match the allowlist.

Run once with `--observe-rollover` to also wait for an actual UTC five-minute transmission, without injected clocks. It records wall-clock boundary evidence separately; this optional natural-window wait can exceed the regular release UI scenario budget. Default verification seals usage through normal quit/restart. For a fixed six-channel surfing/browsing comparison, run `xvfb-run -a node apps/desktop/test/e2e/analytics-app.ts --volume-workload` on each built candidate. An archived old source build can be selected with `--built-desktop=/absolute/path/to/apps/desktop`; that directory must contain `source-revision.txt` naming its actual archive revision. The helper verifies the owned profile, command line and renderer path against the selected build and records its main hash. Its `volumeWorkload` observations retain actual HTTP bodies/counts/bytes, public main-process CPU/fs-write deltas and distinct observed atomic analytics temporary writes. CPU excludes renderer/GPU/FFmpeg; filesystem notification counts are not native rename-latency proof. Focused public-owner tests cover UTC rollover, Brussels/DST timestamps, rollback, channel envelopes, burst durability and exact delta counts. Then disable with the real checkbox, require no captures across restart and the same identity with no duplicate first/day observation after re-enable.

A second profile is seeded with a format-one analytics.json holding daily counts and a queued app_summary_day beside a queued installation_observed. The app must send that installation_observed unchanged, under the seeded identity, never send the summary, and rewrite the file as format two without counts. A third fresh profile faces a refusing loopback capture server: it must retry a refused event with an identical body, hold actual pending events, then clear the persisted queue through Settings opt-out and make no further requests after restart. Unpackaged build attribution is `unknown`. The helper also accepts a packaged executable and optional app arguments, retains its hash/renderer identity and checks its actual version and Stable/Nightly channel. Native installed acceptance stays separate. Inspect screenshots and actual local payloads. Pointer and keys perform mutations; the decoded wire capture establishes results. All five translated controls are checked by focused renderer tests; native platform acceptance remains separate.

The fixture uses a checkout-owned ffmpeg stream of the existing MPEG-TS recording; aborting the owned session ends it. No production broadcast is used for this telemetry acceptance.

## Archived 0.0.15 compatibility

Run `node apps/desktop/test/e2e/analytics-downgrade.ts` from the checkout root. It reads tag `v0.0.15` through Git and executes its actual archived public loader/owner with this checkout's dependencies. The printed `.local/verification/analytics-downgrade-*` directory retains `proof.json` with the exact tag revision, source hashes, consent/identity/legacy-event preservation, unsupported-summary removal on an old-build write, opt-out/re-enable and no revival. A copied schema is insufficient proof.

This helper uses local stores and an injected transport. Its crash is an atomic-file snapshot. It does not exercise an installed old binary, native upgrade or process kill. No-write return recovery and real HTTP delivery need their separate recorded proofs; exact-candidate native acceptance remains on the release card.

## Limits

`docs/privacy.md` holds the published policy, website analytics and attributed provider retention terms. Its version-qualified desktop 0.0.15 and 0.0.16 event list and the Settings note describe the app's events; before release, check them against `docs/telemetry.md`. Loopback payloads prove the integration contract; live ingestion, dashboard counts and server deletion deadlines remain unverified. `apps/desktop/test/analytics.test.ts` checks the owner's public contract: exact local HTTP payloads per event, consent generations for transactions and operations, update-channel stamping, quit flushing of the current run's end-only summary, rate limiting and the 64-event outbox, retries under the same UUID with preserved pending backoff across preference saves and stale-send rejection after consent ABA, format-one migration that discards queued summaries, and opt-out during startup. Its playback cases cover preview eligibility, incident deduplication and recovery, stale bindings and sequences, renderer loss with remote continuation, leases and suspend, consent ABA without historical starts or stops, receiver load failures before and after Output's observer, replay controls and normal-admission fallback. `analytics-open.test.ts` checks that only a current open's own failure reports a fixed code. Receiver terminal ends are checked at the owner (with and without a renderer, against replaced loads, output moves, older runs and opt-out), through a fake Cast receiver in `output.test.ts` (played to its end, Stop, stopped on the TV, release and a broken channel stream) and in the renderer controllers in `renderer/receiver.test.ts`. Public transaction tests check shared refresh, source no-ops, favourite variants/receipts and reorder exclusion, effective preference no-ops and current-target update dismissal. A fake Cast receiver drives generation-guarded main Output observations; it does not establish real AirPlay/Cast hardware acceptance. Renderer contracts check unpaused progress and seek/wait/pause observations without transmitting media positions. Exact-candidate installed native checks stay on the release card. Real-provider playback uses the separate authorized acceptance workflow. `analytics-summaries.test.ts` covers five-minute counted checkpoint writes and explicit pause/stop with additional watch time, a durable zero-time first checkpoint and no waiting/seeking or paused-scrub writes, crash snapshot/restart with stable UUID/original envelope/no dead time, independent consent reads during recovery, optional-block isolation and per-item mixed expiry over actual HTTP, separate admission, all durable items within 64 with both open owners retained, idle retirement of exhausted direct reservations without deleting an active third delivery, and real HTTP body-timeout deliveries capped at three, refused-connect retention, expiry and the 1.5-second fail-closed checkpoint deadline. Interrupted watch duration can lose five minutes plus the lease, and no return means no report. Native installed kill/upgrade/offline and Windows rename/checkpoint latency remain release-owner checks. Saved-report migration precedes merge, and first-nightly reconciliation precedes stable.

Actual renderer exits must be observed from main; main crashes and power loss cannot be claimed from these events.
