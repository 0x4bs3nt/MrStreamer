# Product-use and reliability statistics

## How to get to it

Open Settings > General > Privacy. Share basic usage statistics is on by default. Turn it off with the checkbox; the helper must match the delivered catalogue in `docs/telemetry.md`, and Privacy policy opens the canonical policy in the system browser. No first-use notice or upgrade prompt is shown. Settings > About retains its Privacy link.

## Driving the built app

After `pnpm build`, run `xvfb-run -a node apps/desktop/test/e2e/analytics-app.ts` on headless Linux. The helper owns an isolated profile, loopback capture endpoint and debugging ports. It drives the Settings checkbox with pointer input, observes ordinary preferences and actual capture payloads, restarts the same isolated profile, and retains screenshots, payloads, instance identity and cleanup proof under `.local/verification/analytics-*`. It uses fake provider/TMDB boundaries and a loopback release feed, with automatic updates off. Product mutations use pointer/keyboard input. A verified main inspector advances only the owned process clock by one UTC day for rollover. Production transport is impossible for this isolated profile, even if a release bundle contains production configuration.

Require a checked default and exactly one installation_observed plus one app_active_day before rollover. Drive all ten fixed screen entries, local/copy playback, a failed public open, completed/failed transfers, successful/failed manual update checks and a completed-day summary capture with only allowed raw wire properties. The enabled phase must contain exactly one installation_observed, two app_active_day and one app_summary_day, with no duplicate summary. Force a crash of only the owned renderer, require exactly one main-observed unexpected exit, reload it and require both initial/reloaded starts. Inspect recorded build dimensions, fixed failure codes and terminal success-plus-failure denominators. Then require a visibly unchecked control after disabling, no further captures after disabling or restarting, and the same installation identity with no duplicate first-seen/day capture after enabling again. A second fresh profile faces a refusing loopback capture server, has actual pending events, then clears the persisted queue through Settings opt-out and makes no further requests after restart. Unpackaged build attribution is `unknown`. The helper also accepts a packaged executable and optional app arguments, retains its hash/renderer identity and checks its actual version and Stable/Nightly channel. Native installed acceptance stays separate. Inspect screenshots and actual local payloads. Renderer/service reads establish results; pointer and keys perform mutations. All five translated controls are checked by focused renderer tests; native platform acceptance remains separate.

## Limits

`docs/privacy.md` holds the published policy, website analytics and attributed provider retention terms. Its 0.0.12 daily playback starts, errors and rounded minutes and the Settings note describe the app's expanded counters; before release, check them against the delivered catalogue. Loopback payloads prove the integration contract; live ingestion, dashboard counts and server deletion deadlines remain unverified. `apps/desktop/test/analytics.test.ts` also checks completed UTC aggregates, nested payload sanitization, upgrade attribution, same-day dimension reset including a channel round trip, valid same-channel cross-midnight results, rollback-dropped starts, opt-out generations, bounded checkpoints, old format-one records and saturation. Focused open contracts exercise overlapping public channel requests, stop/cancellation, receiver preview exclusion before the turn, and fixed failure codes. Superseded opens count as interrupted; refused receiver-held previews cannot supersede the receiver request. Focused download/update and renderer tests verify actual-run notifications and entry counts. It checks long foreground/date rollover, upgrade/unknown origins, persistence failure, races, retries, bounded queue and quit deadlines through the public owner and capture contracts. Exact-candidate installed native checks remain on Release 0.0.12. Real-provider playback uses the separate authorized acceptance workflow.

`docs/telemetry.md` defines the delivered event catalogue, rate denominators, exclusions and local dashboard definitions. Policy, FAQ and Opus-approved Settings helper synchronization remain release acceptance requirements. Actual renderer exits must be observed from main; main crashes and power loss cannot be claimed from these counts.
