# Product-use and reliability statistics

## How to get to it

Open Settings > Privacy. Share basic usage statistics is on by default. Turn it off with the checkbox; the helper must match the delivered catalogue in `docs/telemetry.md`, and Privacy policy opens the canonical policy in the system browser. No first-use notice or upgrade prompt is shown. Settings > About retains its Privacy link.

## Driving the built app

It does not advance the clock; UTC rollover of `app_active_day` is covered by the focused owner tests in `apps/desktop/test/analytics.test.ts`. Production transport is impossible for this isolated profile, even if a release bundle contains production configuration.

Require a checked default and exactly one installation_observed, one app_active_day and one app_version_observed. Re-enable observes the current version as unknown_history without repeating installation/day. Every captured raw body must equal its schema-reconstructed allowlist; the proof records the exact property-key set per event name. Drive EPG expansion, a committed favourite and a nonempty search, each with its durable fixed counter. Open the continuous fake broadcast from search; require a persisted admitted journal and no playback HTTP event until its end. Measure at least 34 seconds in Watch, a Home preview of at least 12 seconds with no summary, and return to Watch under the same run. Opening provider VOD emits exactly one ended live summary with at least 32 seconds and no more than observed wall time minus preview plus three seconds. Pause, paused seek and resume preserve the VOD journal UUID and emit no early summary. Watch offline ends that VOD with one summary and admits the next. Completed/cancelled/failed downloads retain direct outcomes. Failed title open reports exactly one typed incident and no summary for that attempt. Quit/restart seals the final usage fragment while preserving identity; every raw HTTP body must match the allowlist.

For the slow-startup recovery check, run `xvfb-run -a node apps/desktop/test/e2e/analytics-app.ts --slow-startup` on headless Linux. Slow-startup analytics runs install an owned filesystem probe before resuming the entrypoint from the inspector. `observed.startupIO` retains up to 32 read/directory/replace measurements per launch, with elapsed start/end times, bounded filesystem error codes, the loaded format number, cached Privacy checkbox state, passive public preference replies and that launch's loopback refusal/body count. ## Installed native telemetry

The long workload is explicit and never enters the ordinary five-minute release-UI aggregate:

```sh
node apps/desktop/test/e2e/analytics-app.ts --native-telemetry \
  --expected-version="$VERSION" --expected-source="$SHA" "$OWNED_INSTALLED_EXECUTABLE"
```

Use Xvfb on headless Linux. On the Mac mini, follow the mac-mini skill and run `onmac check` before any Mac action. Use only an owned DMG-installed bundle, not the daily-driver application or profile. The existing package workflow retains the normal Privacy workload for installed DMG, NSIS, deb, AppImage and test-signed MSIX. Its historical-source exception is restricted to releases through 0.0.15; a newer source without the verifier fails. Signing, Store certification and a Store-delivered update remain separate checks.

Native cases are `consent`, `offline`, `checkpoint`, `periodic`, `seal-send-ack`, `ambiguous`, `quit`, `slow-write`, Windows-only `windows-rename` and `windows-retry`, and `compatibility` when a real prior executable or resolved installed pair is supplied. `--native-case=<name>` runs one case and records that limited coverage. On Mac/Linux, without a packaged executable the same mode drives this checkout's built Electron app; its proof explicitly leaves installed acceptance open. No clock is injected. `periodic` watches five actual counted minutes once, with a real UTC window transmission. Its 330-second failure bound belongs only to that explicit case. Ordinary scenario budgets and CI deadlines are unchanged.

The helper uses actual main-process SIGKILL, not a renderer crash or restored crash snapshot. Windows descendant discovery is prepared while the owned main is quiet, before opening a held-request, atomic-write or future-backoff window. The preparation is consumed only for that same child handle. Proof records each sample start/end/duration and its use time; emergency cleanup without a preparation keeps the existing guarded owner discovery. Native Windows scan latency is unmeasured until the installed run. Public filesystem promise holds select actual before/after checkpoint, seal, attempt-reservation and acknowledged-retirement writes. The driver retains the actual atomic-path record, kills main inside the unchanged 1500 ms serializer deadline and checks recovered UUID/body/envelope/checkpoint time and saved duration without dead time. The loopback sink can close its port, retain a body without answering or accept it. It records raw bytes and socket-close times, reconciles identical retries by UUID and refuses changed bodies. Consent keeps the capture port offline until the active journal and Settings UI are ready, then selects a held body no older than 250 ms before clicking off; a natural HTTP timeout still fails. Direct priority prepares real UI across the first hold/backoff, then requires a real incident to arrive before the persisted eligible time after the second body, with no staging deadline or extra hold. This establishes local retry accounting, not PostHog ingestion/deduplication.

Native close records exit code, signal, forced cleanup and already-exited status. A forced cleanup fails acceptance even if it removes the process. The held-response quit case accepts the window-close stream summary and holds the usage fragment sent after public `will-quit`. It requires its socket to close within the existing 500 ms analytics allowance plus at most 250 ms OS/socket observation tolerance; the ordinary 1000 ms HTTP timeout fails. Whole-app shutdown is checked separately. A native Windows run requires the existing disposable GitHub-hosted runner guard. The file case holds a real .NET read handle without delete sharing, records ordinary rename timings separately from failed replacements, and verifies intact consent/identity and fail-closed UI behavior. `slow-write` holds a public promise over the existing deadline while timers run. It is labelled injected delay and is never described as an OS slow disk.

`windows-retry` is the focused installed NSIS recovery case, also run after ordinary Privacy in the existing Windows package smoke job. It retains the same disposable hosted-runner/executable guard. On real UI guide/favourite writes, the existing filesystem probe opens a real default reader and then an exclusive reader inside the owned Electron main. The exclusive numeric flag is libuv's `UV_FS_O_EXLOCK`, `0x10000000`; the receipt records runtime versions/flags and validates support through actual OS results. Each handle closes synchronously when the first native rename settles, before the product schedules its retry. Default-reader success or denial is diagnostic. At least one real held handle must cause a coded failure followed by success on the same temp basename/bytes; otherwise the case fails and acceptance remains open. Later search must persist and reach HTTP, each action exactly once, with no remaining pending work or duplicate wire UUID. This controlled real-handle case is separate from permanent .NET denial, injected slow-write holds and ordinary unheld rename measurements. It does not identify the actor in an earlier natural collision.

## Limits

`docs/privacy.md` holds the published policy, website analytics and attributed provider retention terms. Its version-qualified desktop 0.0.15 and 0.0.16 event list and the Settings note describe the app's events; before release, check them against `docs/telemetry.md`. Loopback payloads prove the integration contract; live ingestion, dashboard counts and server deletion deadlines remain unverified. `apps/desktop/test/analytics.test.ts` checks the owner's public contract: exact local HTTP payloads per event, consent generations for transactions and operations, update-channel stamping, quit flushing of the current run's end-only summary, rate limiting and the 64-event outbox, retries under the same UUID with preserved pending backoff across preference saves and stale-send rejection after consent ABA, format-one migration that discards queued summaries, and opt-out during startup. Its playback cases cover preview eligibility, incident deduplication and recovery, stale bindings and sequences, renderer loss with remote continuation, leases and suspend, consent ABA without historical starts or stops, receiver load failures before and after Output's observer, replay controls and normal-admission fallback. `analytics-open.test.ts` checks that only a current open's own failure reports a fixed code. Receiver terminal ends are checked at the owner (with and without a renderer, against replaced loads, output moves, older runs and opt-out), through a fake Cast receiver in `output.test.ts` (played to its end, Stop, stopped on the TV, release and a broken channel stream) and in the renderer controllers in `renderer/receiver.test.ts`. Public transaction tests check shared refresh, source no-ops, favourite variants/receipts and reorder exclusion, effective preference no-ops and current-target update dismissal. A fake Cast receiver drives generation-guarded main Output observations; it does not establish real AirPlay/Cast hardware acceptance. Renderer contracts check unpaused progress and seek/wait/pause observations without transmitting media positions. Exact-candidate installed native checks stay on the release card. Real-provider playback uses the separate authorized acceptance workflow. `analytics-summaries.test.ts` covers five-minute counted checkpoint writes and explicit pause/stop with additional watch time, a durable zero-time first checkpoint and no waiting/seeking or paused-scrub writes, crash snapshot/restart with stable UUID/original envelope/no dead time, independent consent reads during recovery, optional-block isolation and per-item mixed expiry over actual HTTP, separate admission, all durable items within 64 with both open owners retained, idle retirement of exhausted direct reservations without deleting an active third delivery, and real HTTP body-timeout deliveries capped at three, refused-connect retention, expiry and the 1.5-second fail-closed checkpoint deadline. Interrupted watch duration can lose five minutes plus the lease, and no return means no report. Native installed kill/upgrade/offline and Windows rename/checkpoint latency remain release-owner checks. Saved-report migration precedes merge, and first-nightly reconciliation precedes stable.

Actual renderer exits must be observed from main; main crashes and power loss cannot be claimed from these events.
