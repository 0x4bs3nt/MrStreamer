# Product-use and reliability statistics

## How to get to it

Open Settings > General > Privacy. Share basic usage statistics is on by default. Turn it off with the checkbox; the helper must match the delivered catalogue in `docs/telemetry.md`, and Privacy policy opens the canonical policy in the system browser. No first-use notice or upgrade prompt is shown. Settings > About retains its Privacy link.

## Driving the built app

After `pnpm build`, run `xvfb-run -a node apps/desktop/test/e2e/analytics-app.ts` on headless Linux. The helper owns an isolated profile, loopback capture endpoint and debugging ports. It drives the Settings checkbox with pointer input, observes ordinary preferences and actual capture payloads, restarts the same isolated profile, and retains screenshots, payloads, instance identity and cleanup proof under `.local/verification/analytics-*`. It uses fake provider/TMDB boundaries and a loopback release feed, with automatic updates off. Product mutations use pointer/keyboard input. Named pointer targets are resolved again after scrolling and hover, require settled geometry and a matching hit, and retain the actual mousedown target in `proof.json`. A verified main inspector advances only the owned process clock by one UTC day for rollover. Production transport is impossible for this isolated profile, even if a release bundle contains production configuration.

Require a checked default and exactly one installation_observed plus one app_active_day before rollover. Drive all ten fixed screen entries, local/copy playback, a failed public open, completed/failed transfers, successful/failed manual update checks and a completed-day summary capture with only allowed raw wire properties. The enabled phase must contain exactly one installation_observed, two app_active_day and one app_summary_day, with no duplicate summary. Force a crash of only the owned renderer, require exactly one main-observed unexpected exit, reload it and require both initial/reloaded starts. Inspect recorded build dimensions, fixed failure codes and terminal success-plus-failure denominators. Then require a visibly unchecked control after disabling, no further captures after disabling or restarting, and the same installation identity with no duplicate first-seen/day capture after enabling again. A second fresh profile faces a refusing loopback capture server, has actual pending events, then clears the persisted queue through Settings opt-out and makes no further requests after restart. Unpackaged build attribution is `unknown`. The helper also accepts a packaged executable and optional app arguments, retains its hash/renderer identity and checks its actual version and Stable/Nightly channel. Native installed acceptance stays separate. Inspect screenshots and actual local payloads. Renderer/service reads establish results; pointer and keys perform mutations. All five translated controls are checked by focused renderer tests; native platform acceptance remains separate.

The expanded scenario also drives EPG expansion and a committed channel favourite, then uses a nonempty global search to open a continuous fake broadcast. It waits for a real confirmed live start and at least 32 seconds of main-owned elapsed watch time. Home preview must preserve the stream while adding no time; returning to Watch must preserve its one start. Provider VOD and a downloaded copy must each confirm playing. VOD pause, a paused seek and resume must keep one start. The allowed autoplay-next preference changes through Settings. A loopback offered update is exposed in its real panel and dismissed through Not now. Completed capture must include all those fixed counters and the daily rounded live minute. The fixture uses a checkout-owned ffmpeg stream of the existing MPEG-TS recording; aborting the owned session ends it. No production broadcast is used for this telemetry acceptance.

## Limits

`docs/privacy.md` holds the published policy, website analytics and attributed provider retention terms. Its 0.0.12 daily playback starts, errors and rounded minutes and the Settings note describe the app's expanded counters; before release, check them against the delivered catalogue. Loopback payloads prove the integration contract; live ingestion, dashboard counts and server deletion deadlines remain unverified. `apps/desktop/test/analytics.test.ts` also checks completed UTC aggregates, nested payload sanitization, upgrade attribution, same-day dimension reset including a channel round trip, valid same-channel cross-midnight results, rollback-dropped starts, opt-out generations, bounded checkpoints, old format-one records and saturation. Focused open contracts exercise overlapping public channel requests, stop/cancellation, receiver preview exclusion before the turn, and fixed failure codes. Superseded opens count as interrupted; refused receiver-held previews cannot supersede the receiver request. Focused download/update and renderer tests verify actual-run notifications and entry counts. It checks long foreground/date rollover, upgrade/unknown origins, persistence failure, races, retries, bounded queue and quit deadlines through the public owner and capture contracts. Expanded public-owner tests exercise midnight splitting, daily rounding across small intervals and output replacement, preview eligibility, failure incidents, stale bindings/sequences, renderer loss with remote continuation, leases, suspend/wall-clock gaps, consent/dimension ABA and populated legacy current/ready/pending migration. The capture boundary checks the new nested dictionaries, known bounds and recursive deletion of private extras. Public transaction tests check shared refresh, source no-ops, favourite variants/receipts and reorder exclusion, effective preference no-ops and current-target update dismissal. A fake Cast receiver drives generation-guarded main Output observations; it does not establish real AirPlay/Cast hardware acceptance. Public contracts also check fresh replay controls through receiver reloads, fresh receiver-open failures after consent/dimension resets, live reset cleanup and late closed-binding failures with stale-generation rejection. Receiver title-load tests distinguish failure before Output creates its observer from adapter failure after it, and completed-day owner captures check one fixed incident without a second open operation, stale callbacks or reset leakage. Public controller admission tests hold or reject optional begin/resume replies across live, VOD, offline copy, receiver preparation/reload/replay, local replay and output returns, while usable media requests proceed with current control hints. Owner captures check normal-admission fallback, reconnects, frame adoption, stale/ended hints and reset renewal. Renderer contracts check unpaused progress and seek/wait/pause observations without transmitting media positions. Exact-candidate installed native checks remain on Release 0.0.12. Real-provider playback uses the separate authorized acceptance workflow.

`docs/telemetry.md` defines the delivered event catalogue, rate denominators, exclusions and local dashboard definitions. Policy, FAQ and Opus-approved Settings helper synchronization remain release acceptance requirements. Actual renderer exits must be observed from main; main crashes and power loss cannot be claimed from these counts.
