## Decision summary

- The iOS FFmpeg build **uses dynamic libraries**, not static FFmpeg archives. The static setting belongs to the TitleFormats wrapper. Dynamic packaging does not, by itself, resolve LGPL replacement requirements or the GPL app's App Store distribution terms.
- Optional PostHog statistics remain pseudonymous collection after consent. Preserve the prior recommendation of **Device ID, Product Interaction and Other Diagnostic Data; Analytics; Linked Yes; Tracking No for the confirmed PostHog flow**, pending current configuration and candidate evidence. Do not turn this into an app-wide clearance while TMDB and hosting practices remain unresolved.
- The historical `ba1c7aa7` source defaults statistics on; merged PR #345 requires a saved affirmative choice. Affirmative consent, migration of previous default-on profiles and rejection of pre-consent queued work are approved requirements, not established behavior of this baseline.
- TMDB's API documentation establishes application authentication and image delivery. It does not answer end-user API/CDN retention, identity linkage or advertising reuse. Current policy/terms retrieval failed; the earlier sheet's account of the broader policy remains historical evidence, not a fresh policy verification.
- The reviewer Worker has no request logger or user database and its checked-in deployment configuration disables observability. There is no configured live target in that file. Cloudflare request processing, invocation logs, other account logs and vendor Network Data need their own evidence. Credentials in Xtream request URLs make this material.
- Original sample provenance is substantial and locally consistent. It supports investigation of rights to those exact samples, not permission to stream or download arbitrary subscription media or use unrelated artwork.
- GPL corresponding source, LGPL compliance and Apple contract compatibility are separate gates. The present licence inventory and private TestFlight delivery do not pass them for a public candidate.

An API key is a query parameter or a read token is a Bearer header. Images are separate HTTPS requests to `image.tmdb.org` paths. Search matching is local against provider/catalogue and cached metadata in the inspected iPhone flow. The inspected TMDB caller does not add the analytics installation UUID, provider password or typed search text. ### 3.2 Why this does not authorize arbitrary provider content

Apple's rules separately require permission for third-party services/materials and explicit source authorization for downloading; authorization can be requested in review. Prepare a rights packet that distinguishes:

### 4.3 GPL obligations of the app itself

The following are **licence-text requirements**, not a conclusion that Apple's delivery method satisfies them:

- GPLv3 §1 defines Corresponding Source to include modification/build/install/run source and controlling scripts, with specified System Library/tool exceptions. A JavaScript bundle, licence list or floating repository link is not the complete required source set.
- §§4–5 address notices, licence, warranty/change information and appropriate legal notices for interactive interfaces. §6 governs object-code distribution and the selected source-delivery method. For a network route under §6(d), maintain equivalent access and clear directions for the exact source; continued availability remains the distributor's responsibility.
- §§3, 10 and 12 address anti-circumvention rights, further restrictions and incompatible external conditions. Being free of charge does not remove these terms.

[GNU GPLv3 text, §§1, 3–6, 10, 12][gpl3]; [repository licence][r-license].

**Recommendation:** prepare a version-bound public source package with app/shared native and TypeScript source, exact dependency versions/source material, local patches, build/configuration scripts, toolchain instructions and component notices. Identify genuine System Libraries rather than assuming all Apple-related or prebuilt code qualifies. Explain how readers obtain exact source from the app's notice and Store-adjacent distribution information. A locked dependency graph or tarball URL alone does not prove a future recipient can rebuild the distributed work. GNU's source-access FAQ supports exact-version instructions. [GNU FAQ][gnu-source].

GPLv3 §6's Installation Information duty has a **specific transaction condition** involving conveyance in/with/specifically for a User Product and transfer of possession/use of that product. Do not reduce it to “every iOS app must disclose the developer's signing key,” or assume it never applies because the app is a download. Assess the actual distribution transaction and parties, what information is needed for modified versions, and whether a compliant route exists. The separate no-further-restrictions question remains even if that condition is not triggered. No signing key was requested or exposed in this research. [GPLv3 §6][gpl3].

### 4.4 LGPL obligations for bundled FFmpeg

LGPL-2.1 §4 requires corresponding library source for distributed library binaries. §6 permits a linked work under stated conditions, including notices/licence and modification/reverse-engineering permissions, plus an applicable compliance route. A suitable shared-library mechanism under §6(b) must work with an interface-compatible replacement installed by the user; §6(a) instead provides library source plus the complete work using it in source and/or object form for relinking. These are alternatives with conditions, not a rule that a `.framework` suffix automatically discharges the obligation. [LGPL-2.1 §§4–6][lgpl21].

**Inference for iPhone:** signing, provisioning and Store delivery can obstruct replacement of embedded frameworks. This run has not demonstrated a permitted user replacement/rebuild/install route for the delivered candidate. Select and document the actual LGPL route rather than claiming easy library replacement. The GPL app's complete buildable source may contribute to a §6(a) route; merely linking to the repository does not demonstrate it. Supply build/configuration and any needed relink material, and test the documented procedure with a compatible modified library. A change to static FFmpeg in a future artifact would require a fresh assessment, not retroactive assertion that this build was static.

FFmpeg's compliance checklist recommends dynamic linking, exact source distribution, build instructions, notices and removal of reverse-engineering prohibitions. It expressly describes an easy compliance approach, not the only legal route. Do not mistake its same-webserver recommendation for resolution of Apple's delivery or §6's precise conditions. FFmpeg supplies no separate proprietary licence as a shortcut. [FFmpeg legal checklist][ffmpeg-legal]; [GNU linking explanation][gnu-linking].

Maintain the exact FFmpeg archive and hash, original licence files, source modifications or an explicit verified no-source-patches statement, configure/toolchain record, framework packaging transformations and the chosen source/relink procedure. Include the app changes needed to use the library and preserve permissions in any EULA. Archive/export evidence must confirm the bundled notices and public source directions.

### 4.5 Apple terms: concrete tension, no clearance asserted

Apple's free-app route uses the Developer Program agreement and Schedule 1. It requires FOSS compliance while protecting non-FOSS Apple software; Schedule 1 §3.2 permits a custom EULA subject to Exhibit B minimums. Those minimums include a nontransferable Apple-device/Usage-Rules licence. Obtain the account's accepted English agreement and region-specific terms, not only today's public page. [Program agreement, §3.3.4(A)(v), §7.1, Schedule 1 and Exhibit B][apple-program]; [agreement authority][apple-terms].

The Standard EULA restricts transfer/redistribution and modification/reverse engineering, with an express open-source licensing exception to the latter restrictions. Preserve that qualification when evaluating it. A custom EULA is a tool to inspect, not an established cure for other contract or delivery restrictions. [Standard EULA][apple-eula]; [custom-EULA process][apple-custom-eula].

Apple Media Services Usage Rules add restrictions on service/content use and security technology. Their application varies with territory and the relationship involved. These create concrete questions against GPL §§3/10/12 and LGPL §6; an open-source exception in one paragraph does not answer all of them. [Media Services terms, §§F/O][apple-media]; [GPL][gpl3]; [LGPL][lgpl21].

**Owner/legal blocker:** record a reasoned analysis for the exact app, bundled components, chosen EULA, actual accepted Apple agreements, signing/delivery and source/relink route. It must address redistribution/modification permissions, applicable Usage Rules, source availability and any Installation Information condition. If conflicting conditions cannot be reconciled, GPL §12 does not waive GPL compliance. Previous App Store acceptance of another GPL app, or this app's TestFlight processing, would not establish these permissions. Do not change the app licence, invent a linking exception, assume authority over contributors' rights or claim Apple has waived its terms. Any exception/relicensing path would need authority from the relevant rights holders and a new decision outside this dossier.
