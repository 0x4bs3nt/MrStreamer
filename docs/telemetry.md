# Product and reliability measurements

The main-process `Analytics` owner controls consent, installation identity, fixed daily counters and the durable outbox. Collection uses the existing default-on statistics preference. These definitions describe the payload contract and local queries; they do not change a live PostHog project or establish live ingestion or retention.

## Questions and events

| Event                   | Question                                                                                    | Frequency                                                  |
| ----------------------- | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| `installation_observed` | Which profiles were first observed using a configured build?                                | Once per profile, unchanged                                |
| `app_active_day`        | Which installations use the primary window in the foreground?                               | Once per UTC foreground day, unchanged                     |
| `app_summary_day`       | Which screens/actions/preferences are used, what plays, and how do observed operations end? | At most one completed-day aggregate per UTC foreground day |

The existing envelope contains a random installation UUID, event UUID and delivery-observation timestamp. The installation identifier is pseudonymous, not anonymous. Properties are `app_version`, `build_channel`, `update_channel`, `os`, `arch`, `distribution`, `profile_origin`, `$process_person_profile: false` and `$geoip_disable: true`. Activity adds `activity_date`; summaries add `summary_date` and `counts`. There are no individual action timestamps or content identities.

Each aggregate and completed snapshot records its own build dimensions. An upgrade before rollover cannot relabel prior-day counts. A dimension change within one UTC day resets current counts. This intentionally loses partial-day coverage; it never creates a per-build history or multiple summaries for that day. Outcomes of operations spanning a selected-channel change are excluded, including a change back to the original channel. Repeating the same channel preserves valid results, including across midnight.

## Fixed counters

`counts.features` has only `home`, `live_tv`, `movies`, `series`, `watchlist`, `downloads`, `search`, `settings`, `player` and `details`. Renderer notifications carry a single validated literal. Page changes and closed-to-open overlays count entries. Re-renders, text input, Settings tab changes and switching between player modes do not count again. Details count when visible, including a return from playback. Main owns all counters and outgoing payloads.

Each of `playback_open`, `download_transfer` and `update_check` has `started`, `success`, `failed`, `interrupted` and `failures`. Failures have only `network`, `credentials`, `unsupported`, `disk`, `unavailable` and `app` counters.

| Operation           | Observed start and terminal meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `playback_open`     | One validated public `playback.open`, `playback.openTitle`, `playback.openCopy`, `output.playChannel` or `output.openTitle` handler execution. Success means the request resolved. Superseded opens and cancellation count as interrupted. A Home preview refused because a receiver holds playback is excluded before its turn and start. This includes accepted Home preview opens and prepared receiver-title opens; it does not prove displayed video, audible sound or a receiver's subsequent title load. |
| `download_transfer` | One leased transfer run, including file resolution and final rename. Success means the complete copy was kept. Failure includes transfer, disk and finalization failures. Cancellation, playback preemption and observed shutdown interruptions are separate. Queue additions, duplicate additions, progress and artwork fetching are excluded.                                                                                                                                                                 |
| `update_check`      | One actual shared release-discovery fiber, including automatic checks and channel changes. Success means discovery answered, even with no offered release. Awaiting callers do not multiply counts. Installer downloads and installation are excluded.                                                                                                                                                                                                                                                          |

Started and terminal counts use the UTC day on which main observes them, independently. A request starting before midnight and finishing afterward has a start on the earlier day and a result on the later one. Unfinished attempts and outcomes main never receives cannot be reconstructed.

Classification reads typed failure kinds and bounded HTTP status categories only to select a code. It never copies an exception, message, status number, log, stack, URL, path, title, channel, provider or search query. A refused stream with HTTP 401/403 maps to `credentials`; other refusals and unavailable/provider-error streams map to `unavailable`. Network and unsupported stream kinds keep those codes. Download folder/full-disk failures map to `disk`. Typed provider HTTP errors map to `unavailable`; unknown app failures map to `app`. Feed offline failures map to `network`; invalid feeds map to `app`; HTTP/rate-limit failures map to `unavailable`.

`counts.renderer` contains `starts`, `crashed`, `killed` and `other`. Main observes primary-window loading and Electron `render-process-gone` reasons. Clean exits, actual requested window closes and app shutdown are excluded. Reloads are new starts. These counts cannot observe a main-process crash, power loss or an OS termination main never receives. No crash report or raw exit reason leaves the process.

## Confirmed playback

`counts.playback` has exactly `live` and `vod`. Each has `starts`, `errors`, `failures` with the same six fixed categories, and `watch_minutes`. VOD includes provider movies, episodes and downloaded copies. There is no provider/source-type breakdown and no recording counter. The app does not implement media recording.

Gameplay admission never awaits a separate analytics reply. Live/VOD/copy opens, receiver preparation/loads and existing-session replay carry an ephemeral control hint independent of advisory registration. Main validates the current trusted frame, order and actual playback kind, mints its own run/binding UUIDs, and resolves facts only against the current control and binding. Controls and frame associations remain in bounded memory only; they never enter daily records or capture. A delayed, rejected or absent measurement reply cannot delay opening media. Repeated current hints keep one run; an explicit replay gets a fresh hint; superseded or ended hints cannot restart an old run.

A start is the first confirmed eligible playing interval of a logical viewing run. Resolving an open, loading a receiver or holding a VOD first picture paused does not count. Local engines report unpaused clock progress; receiver state comes from the main Output service after its load-generation guard. The latter establishes receiver-confirmed playing, not audible sound or a displayed picture. Automatic Home/guide previews are excluded. Promoting a playing preview to Watch starts observation then. Returning to preview suspends measurement; returning to Watch resumes the same logical start. Intentional mute in Watch and the mini player remain eligible.

Reconnects, quality/audio/track changes, seeks and output moves keep the logical run. Only one physical binding may accrue time. Old sessions, engine callbacks, binding sequences and receiver loads cannot renew another binding. Main session closure, renderer termination/reload and shutdown settle local playback. Renderer loss leaves genuinely continuing receiver playback under main ownership. Adopting that receiver in a new window creates no historical start. Explicit replay and the next episode start new runs.

An error is one observed failed start after internal format/repair fallback, or one interruption of confirmed playback entering recovery. Repeated attempts in that incident do not count again. Confirmed recovery closes the incident, so a later break can count again. Public open failures and engine classification share the incident guard. Supersession, explicit stop, pause, preview refusal and shutdown are excluded. `playback_open.failed` remains a different request-level measurement; do not add it to playback errors.

A receiver title's preparation is its one `playback_open` operation. If its later load fails before Output creates a physical observer, the current run records a playback incident without another open operation. Once Output creates that observer, it owns load and adapter failures.

Main uses monotonic elapsed wall time, never title positions, playback speed, receiver interpolation or engine played-time totals. One minute at 2x speed is one watch minute. Pauses, buffering, seeking, replacement/recovery gaps and preview-only intervals stop accrual. Engines renew bounded state every second; local state expires after five seconds and receiver state after fifteen seconds unless the authoritative producer confirms it again. Notification cadence and lease expiry bound observation error. These measurements do not establish viewer attention. A suspended app requires fresh state after resume; a stalled main loop accrues at most its last confirmed lease. A UTC wall-clock jump inconsistent with the monotonic clock drops the uncertain interval.

Private `watch_ms.live` and `watch_ms.vod` live only in the fixed local daily buckets. Main settles at every note, bucket/dimension change, binding/state change and quit, plus a one-second sample. Stable intervals split at UTC midnight before a completed bucket is queued. Each day's kind rounds once with `Math.floor((watch_ms + 30_000) / 60_000)`. The wire contains only integer `watch_minutes`, bounded to 0..1440 per kind. Combined private live/VOD time is capped at 86,400,000 ms per UTC day; impossible additions mark saturation. Rounding error is at most half a minute per kind per day. Separately rounded live plus VOD may differ from rounding their combined time by up to one minute.

## Consent and bounds

Opt-out pauses collection synchronously before queued disk writes, aborts the owned request, clears pending events and clears daily counts. Restart stays off. Re-enable starts fresh counting; an operation can report its result only in the enabled generation and dimensions that observed its start. Disabled activity and old pending counts are never backfilled. Installation first-seen and daily foreground observation semantics remain unchanged. Opt-out retains the installation identity and first-seen/day ledger; it clears collection and delivery data, not identity. Playback bindings are invalidated synchronously, including a consent or dimension round trip. Enabling during continuing playback observes future confirmed time without backfilling the disabled interval or synthesizing a historical start.

Unconfigured builds count and send nothing. Development, automated and isolated profiles cannot use production capture. An isolated local verifier can explicitly select a literal loopback endpoint; it cannot fall back to production or follow redirects there.

Memory and persisted state retain the current UTC bucket and at most one completed bucket. Newer completed days replace older unsent buckets. Foreground observation queues a completed summary once, within the existing eight-event outbox and three attempts per event across restarts. Expiry and offline losses reduce coverage. Clock rollback drops notes until the current observed day is reached and never reopens reported days. A dropped start supplies no token, so its later result is also excluded.

Existing and new count fields stop at 1,000,000; watch minutes use the tighter physical bound above. `counts.saturated` marks any clipped increment. Exclude saturated summaries from rates. Notes mutate fixed-size memory and never wait for playback or transfers. One delayed checkpoint and one dirty flag coalesce bursts through the existing disk serializer; notes cannot create a per-action persistence queue. Foreground/outbox writes also checkpoint counts. Shutdown retains its 500 ms total wait; a hung disk or transport fails closed. Very recent uncheckpointed notes can be lost on abrupt termination.

## Persisted legacy state

Format-one files with populated old current/ready summaries retain every existing feature, operation, failure and renderer count, saturation flag, day, saved dimensions, reported day, consent, identity and observation ledger. Missing new fixed keys and private durations zero-fill in local buckets. The loader validates known values before filling defaults, deletes unknown keys recursively and fails closed on invalid known counts without logging raw parse values. Raw daily duration is local only.

Queued legacy captures keep their original missing fields, UUID, timestamp and attempt count. Their retries do not gain new properties under an existing event UUID. Expanded fields already present survive validation; a permissive legacy branch cannot erase them. Reported days are not reopened. A migrated zero-filled day did not observe the new measurements for its whole day; it is not evidence of zero adoption.

## Local dashboard definitions

Group comparisons by recorded `app_version`, `build_channel`, `update_channel`, `os`, `arch` and `distribution`. Deduplicate events by UUID when inspecting capture attempts.

- Confirmed viewing starts are `sum(playback.live.starts) + sum(playback.vod.starts)` from `app_summary_day`, grouped by `summary_date`. Replace the old Daily stream starts card's `stream_started` definition with this aggregate. Those individual events are not emitted.
- Daily watch time is `sum(playback.live.watch_minutes) + sum(playback.vod.watch_minutes)`. Replace the old Average watch duration card's `stream_stopped` definition and title with Daily watch time, unit minutes. The app emits no stop event or completed-stream duration. If a quotient is needed, label it Watch minutes per start in selected period, using `sum(minutes) / sum(starts)` with zero denominator null. It is a period volume ratio, not average completed-stream duration. A day's watch time can belong to a run started the day before.
- Playback incidents are `sum(playback.<kind>.errors)`; failure bars sum its fixed category counters. Errors per start is an incident frequency, can exceed 100%, and is not a playback success percentage.
- Feature/action/preference adoption for a day/build is the number of distinct installations with a positive fixed feature/action/preference count divided by distinct installations with a received summary for that day/build.
- Operation reliability is `sum(success) / (sum(success) + sum(failed))`. Report the denominator beside the rate. Starts show volume and unmatched/in-flight attempts; interruptions stay separate. A zero terminal denominator yields no rate.
- Failure-category bars sum the six fixed failure counters for each operation.
- Renderer stability is `(sum(crashed) + sum(killed) + sum(other)) / sum(starts)`, with the observation limits above. A zero start denominator yields no rate.

Exclude saturated summaries from these calculations and recommended totals, and show the missing coverage. Use numeric nested-property access and SUM, not COUNT(summary events). Filter `summary_date` for the UTC observation period; delivery `timestamp` can arrive on a later day. Exclude pre-expansion missing fields from new-metric adoption denominators and state the rollout/migration coverage. Existing installation, active-day and origin cards keep their existing event definitions; create no duplicate dashboard. Private saved query definitions, nested casts and ingestion UUID deduplication still need validation in the private project.

Exclude saturated summaries from these calculations. Keep existing first-seen and foreground-active views separate. Received-summary coverage is not the entire active population. Short-lived users who never return, consent changes, partial-day dimension resets, offline expiry, startup before consent and selected-channel dimensions are known and interrupted processes all limit coverage.
