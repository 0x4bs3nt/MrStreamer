# Product and reliability events

The main-process `Analytics` owner controls consent, installation identity, playback runs and the durable outbox. It is the only producer of capture events; renderer notifications carry validated fixed categories and optional fixed playback context, never free text. Collection uses the existing default-on statistics preference. These definitions describe the payload contract and local queries; they do not change a live PostHog project or establish live ingestion or retention.

In desktop 0.0.15, as since 0.0.14, the app sends one event per observed action, playback run or outcome. It no longer sends `app_summary_day` daily aggregates.

## Envelope

Every event has a random event `uuid`, the pseudonymous installation UUID as `distinct_id` and the `timestamp` at which main queued it. Every event's properties include `app_version`, `build_channel`, `update_channel`, `os`, `arch`, `distribution`, `profile_origin`, `$process_person_profile: false` and `$geoip_disable: true`, with the values current when the event was queued. The transport validates each event against its fixed schema and copies each allowed field by name; no other field reaches the wire.

`error_type` is one of `network`, `credentials`, `unsupported`, `disk`, `unavailable` and `app`. VOD covers provider movies, episodes and downloaded copies; catch-up of a live channel is `live`. There is no provider, source type, title, channel, content or stream identifier.

### Not sent

- `recording_started`: the app cannot record. "Recording" in its source means a provider's catch-up archive, which plays as a `live` run, and Downloads are reported by `download_ended`. Neither is relabelled as recording.
- A search result count: `search_used` is queued at the first nonempty query of an episode, before any of its result sources has answered. No search text is ever sent.
- Per-request open outcomes and renderer start counts from the daily summaries. Stream events replace the former; use `app_active_day` as context for `renderer_exited`, which has no per-launch denominator.

## Playback runs

Gameplay admission never awaits a separate analytics reply. Live/VOD/copy opens, receiver preparation/loads and existing-session replay carry an ephemeral control hint. Main validates the current trusted frame, order and actual playback kind, mints its own run/binding UUIDs, and resolves facts only against the current control and binding. Controls, frames and bindings stay in bounded memory and never enter persisted state or capture. A delayed, rejected or absent measurement reply cannot delay opening media. Repeated current hints keep one run; an explicit replay gets a fresh hint; superseded or ended hints cannot restart an old run.

`stream_started` is the first confirmed eligible playing interval of a run. Resolving an open, loading a receiver or holding a VOD first picture paused does not count. Local engines report unpaused clock progress; receiver state comes from the main Output service after its load-generation guard, which establishes receiver-confirmed playing, not audible sound or a displayed picture. Automatic Home/guide previews mint no run. Promoting a playing preview to Watch starts the run then; returning to preview suspends measurement and returning to Watch keeps the same run. Intentional mute in Watch and the mini player remain eligible.

Reconnects, quality/audio/track changes, seeks and output moves keep the run. A new run ends the previous one: another channel, title, copy, explicit replay or the next episode. Explicit stop, renderer termination or reload of a local run and quit also end it. On a receiver, main Output ends the run itself when the viewer stops it, the receiver stops it without a stream failure, a title plays to its end or its subscription goes, whether or not a window is open. Reloading for tracks or position, a broken stream awaiting retry, a lost or released receiver and moving output only end that load's observation, never the run. Renderer loss leaves genuinely continuing receiver playback under main ownership; adopting it in a new window keeps its run. A title stopped on the receiver and played on from the app is a new run.

`watch_duration_seconds` is main's monotonic elapsed time while the current binding reported eligible `playing`, rounded once to whole seconds. It never uses title positions, playback speed, receiver interpolation or engine played-time totals, so one minute at 2x speed is 60 seconds. Pause, buffering, seeking, replacement/recovery gaps, preview and suspend add nothing. Engines renew state every second; local state expires after five seconds and receiver state after fifteen unless the authoritative producer confirms it again, which bounds a stalled producer's error. These durations do not establish viewer attention.

From desktop 0.0.16, the existing `stream_error` can also contain these optional properties. This adds no event, changes no coarse `error_type`, and does not change iOS capture. Desktop 0.0.15 and historical events lack this context and must be treated as unknown.

| Property                 | Fixed values                                                                                                                                                                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `diagnostic_stage`       | `open`, `probe`, `inspect`, `convert`, `decode`, `deliver`, `unknown`                                                                                                                                                                       |
| `diagnostic_reason`      | `tool_missing`, `tool_failed`, `probe_failed`, `malformed_input`, `unsupported_input`, `decode_rejected`, `copy_rejected`, `conversion_failed`, `inspection_undetermined`, `network`, `provider_refused`, `provider_unavailable`, `unknown` |
| `diagnostic_container`   | `mpegts`, `hls`, `mp4`, `matroska`, `other`, `unknown`                                                                                                                                                                                      |
| `diagnostic_delivery`    | `direct`, `converted`, `unknown`                                                                                                                                                                                                            |
| `diagnostic_video_codec` | `h264`, `hevc`, `mpeg2`, `vp8`, `vp9`, `av1`, `unknown`                                                                                                                                                                                     |
| `diagnostic_audio_codec` | `aac`, `mpeg_audio`, `ac3`, `eac3`, `dts`, `opus`, `flac`, `unknown`                                                                                                                                                                        |
| `diagnostic_fallback`    | `none`, `audio`, `video`, `repair`, `unknown`                                                                                                                                                                                               |

These are facts available at the reporting boundary, not the media's identity. Container describes the inspected input in main, or the delivered format when only the renderer knows it. Delivery says whether a known plan converts any picture or sound; fallback identifies the compatibility step, not an attempt number. Codec families come only from typed inspection/probe facts. An unresolved conservative inspection guess stays unknown. No message, stderr, path, URL, provider, login, content identifier or arbitrary codec name is collected. Decode rejection does not establish that a decoder is missing. Unknown or absent context never establishes a codec cause.

Capture and IPC validation reject unknown diagnostic literals. On disk, future optional diagnostic values are omitted independently, retaining valid consent, identity and legacy queued events. The actual 0.0.15 loader deletes these additive properties and preserves the old event and all its existing enum values. No new event name enters the legacy queue in D1.

A run that never confirmed playing sends neither a start nor a stop. `stream_error` needs no start: a failed open, after internal format/repair fallback, sends one error and nothing else. Repeated attempts within an incident do not send again; confirmed recovery closes it, so a later break sends again. Public open failures, engine classification and receiver loads share the incident guard. Supersession, explicit stop, pause, preview refusal and shutdown are not errors. A receiver title's load that fails before Output creates its physical observer reports for the current run; afterwards Output owns load and adapter failures.

## Producers

Feature entries count page changes and closed-to-open overlays. Re-renders, text input, Settings tab changes and switching between player modes do not count again. Details count when visible, including a return from playback.

| -------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `channel_changed`    | Explicit selection of a different logical channel, even if the replacement fails.                         | First selection, same-channel retry, quality/track choice, output move and preview selection.                                  |
| `playlist_added`     | A new saved source committed by Subscriptions; Xtream and M3U are both sources.                           | Re-entering a saved login, renaming and credential repair. No source type or identity.                                         |

The `setting_key` rows are `settings_changed`. Preference comparisons happen inside Settings' file serializer and notifications follow successful persistence. Update channel and dismissal observations belong to Updates; source and refresh observations to their committed operations; favourites to the viewing transaction. These are preference-change events, not a claim that every change came from the Settings screen. Volume/mute, consent, TMDB keys, provider/guide configuration, credentials, last channel/category and title/variant choices are excluded.

Classification reads typed failure kinds and bounded HTTP status categories only to select a code. It never copies an exception, message, status number, log, stack, URL, path, title, channel, provider or search query. A refused stream with HTTP 401/403 maps to `credentials`; other refusals and unavailable/provider-error streams to `unavailable`. Download folder/full-disk failures map to `disk`. Feed offline failures map to `network`, invalid feeds to `app`, HTTP/rate-limit failures to `unavailable`; unknown app failures map to `app`.

## Consent and bounds

Opt-out pauses collection synchronously before queued disk writes, aborts the owned request and clears unsent and pending events. The current playback run is dropped without a `stream_stopped`. Restart stays off. Re-enable sends nothing about the disabled period: a run continuing across it sends no start, no stop and no historical duration, and transactions or operations that began while disabled, or before an opt-out, report nothing. Opt-out keeps the installation identity and first-seen/day ledger. Update-channel changes do not end runs; each event carries the channel current when it was queued.

Unconfigured builds send nothing. Development, automated and isolated profiles cannot use production capture. An isolated local verifier can explicitly select a literal loopback endpoint; it cannot fall back to production or follow redirects there.

Events need the installation identity, which the first foreground observation creates; anything earlier is dropped. New direct captures are limited to 60 per minute and the excess is dropped; first-seen/day observations, queued events and retries are outside that limit. A burst coalesces into one serialized outbox write, so playback, transfers and the UI never wait for disk or network, and playback time accrues in memory without per-second writes. The persisted outbox holds at most 64 events; when full, the oldest are dropped, keeping a pending first observation. Each event is sent straight away, one request at a time, with three attempts in all, across restarts, under its original UUID and timestamp. Quit queues the current run's stop first and keeps its 500 ms total wait; abrupt termination can lose the latest unflushed events, including a stop. Offline expiry, rate limiting and these losses reduce coverage; a start without a matching stop is expected.

## iOS app

The iOS app (`apps/ios/src/telemetry/`) has its own owner with the same event names, literals and bounds wherever it has the same observation. It is on by default: Settings' Privacy section has the switch, Share basic usage statistics, which saves the choice at once and keeps it across launches, an earlier off included. With it off, or in a build without a capture configuration, nothing is recorded or sent; Settings says when a build sends nothing or only to a local endpoint.

Every iOS event's properties are `app_version` (app.json's version), `app_build` (the binary's `CFBundleVersion`), `os: "ios"`, `os_major` (iOS's major version, when readable), `$process_person_profile: false` and `$geoip_disable: true`. There is no `arch`, `build_channel`, `update_channel`, `distribution` or `profile_origin`, and no device model, locale or other device detail. Filter app reports by `os` to keep iOS and desktop apart; `app_version` alone matches both.

| Event                                              | iOS producer                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `installation_observed`, `app_active_day`          | The app active on screen, as on desktop.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `stream_started`, `stream_stopped`, `stream_error` | The one player. A run is one viewer request, kept across Try again; another channel or title or Stop ends it. Watch time counts while AVPlayer reports playing and the viewer sees or hears it: Watch, Picture in Picture, AirPlay or a preview they unmuted. Home's silent preview, pauses, buffering and the app in the background without Picture in Picture or AirPlay add nothing; a playing state counts for five seconds unless the position moves on. Open failures map their typed error as desktop does; AVPlayer's own failures carry no type and report `unsupported`. Failures of the silent preview aren't reported. |
| `feature_opened`                                   | Entering `home`, `live_tv`, `movies`, `series`, `details`, `search`, `settings` or `downloads`, and `player` when Watch opens from the tabs. Moving within one screen counts once, except each title's details.                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `search_used`                                      | The first nonempty text in Search, until it is cleared or the viewer leaves Search.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `channel_changed`                                  | Choosing another channel to watch in Live or Search while a channel plays or failed, even if the new one fails. Not the first choice, the same channel again, Home's silent preview or Stop.                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `playlist_added`, `playlist_removed`               | A new subscription committed to the registry, or one actually removed. Adding a saved account again, renaming and entering a password again send nothing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `playlist_refreshed`                               | A subscription's channel list loaded and committed: at launch, after an add, a retry or a reload. Movie and series lists don't count.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

iOS sends no `epg_opened`, `favourite_added`, `settings_changed`, `update_*` or `renderer_exited` events. Downloads are available, but their outcomes are not yet instrumented: no `download_ended`.

iOS ends apps in the background without telling them. While a reported run plays, and when the app leaves the foreground, its stop as it stands is saved; the next launch sends it under the same UUID unless the run ended normally first. Consent, outbox, retries and the 60-a-minute limit follow the desktop rules above, except that a retry waits ten seconds and requests time out after five. Production capture needs a release bundle with `EXPO_PUBLIC_MR_STREAMER_ANALYTICS_RELEASE_BUILD=1`, an approved `EXPO_PUBLIC_MR_STREAMER_ANALYTICS_HOST` and a `phc_` `EXPO_PUBLIC_MR_STREAMER_ANALYTICS_PROJECT_TOKEN`. A development bundle can only use a loopback `EXPO_PUBLIC_MR_STREAMER_ANALYTICS_LOCAL_ENDPOINT`. React Native's `fetch` follows redirects, which desktop's transport refuses. Verify the contract through `apps/ios/test/telemetry.test.ts`.

## Persisted legacy state

Format-one `analytics.json` files held daily summaries. Loading one discards its current/ready counts and any queued `app_summary_day`, which are never sent, and immediately writes format two. Consent, identity, origin, the first-seen/day ledger and other queued events keep their UUID, timestamp and attempt count. Unknown keys are deleted and invalid known values fail closed without logging raw values.

## Local dashboard definitions

Group by recorded `app_version`, `build_channel`, `update_channel`, `os`, `arch` and `distribution`. Deduplicate by event UUID.

- Stream starts: count `stream_started`, split by `stream_type`.
- Watch time: sum `watch_duration_seconds` of `stream_stopped`, divided by 60 for minutes. Average watch duration is that sum divided by the number of `stream_stopped`. A stop's time belongs to its stop timestamp.
- Playback errors: count `stream_error`, broken down by `error_type`. Errors per start is an incident frequency, can exceed 100% and is not a success rate.
- Feature, action and setting adoption: distinct installations with the event, divided by distinct installations with `app_active_day` in the period.
- Download and update-check reliability: `success / (success + failed)` over `*_ended` outcomes, with the denominator shown. `interrupted` stays separate.
- Renderer exits: count `renderer_exited` by `reason`, beside active installations.

Insights still built on `app_summary_day` describe builds up to 0.0.13 only. Private saved queries and ingestion deduplication need validation in the private project. Verify the contract through `apps/desktop/test/analytics.test.ts` and the built-app Privacy feature-map path. Settings, FAQ and privacy-policy claims must match this catalogue before release.

After 0.0.16 is distributed, the release owner must check a read-only breakdown of `stream_error` by app version, OS, stream type and these fixed fields, keeping absent historical context labelled unknown. Compare incident counts with the unchanged coarse `error_type` report and re-baseline against 0.0.15 as traffic arrives. The 0.0.14 exploratory sample cannot identify missing codecs, affected installations or the effect of 0.0.15 recovery. Engineering loopback events are not production evidence. No live PostHog report is changed by this unit.
