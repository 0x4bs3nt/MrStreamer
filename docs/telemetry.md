# Product and reliability events

The main-process `Analytics` owner controls consent, installation identity, playback runs and the durable outbox. It is the only producer of capture events; renderer notifications carry validated fixed categories and optional fixed playback context, never free text. Collection uses the existing default-on statistics preference. These definitions describe the payload contract and local queries; they do not change a live PostHog project or establish live ingestion or retention.

Desktop 0.0.15 sends individual actions and playback boundaries. From desktop 0.0.16, usage is grouped into durable five-minute `usage_window` delta fragments and each admitted play sends one `stream_summary` only when it ends. Errors, outcomes and installation/day observations stay direct. iOS remains unchanged. Neither desktop version newly sends `app_summary_day`.

## Envelope

Every event has a random event `uuid`, the pseudonymous installation UUID as `distinct_id` and the event `timestamp`. Usage fragments use their original UTC five-minute window start; all other events use their observed terminal or direct-capture time. Every event's properties include `app_version`, `build_channel`, `update_channel`, `os`, `arch`, `distribution`, `profile_origin`, `$process_person_profile: false` and `$geoip_disable: true`, with the values current when the event was queued. The transport validates each event against its fixed schema and copies each allowed field by name; no other field reaches the wire.

`error_type` is one of `network`, `credentials`, `unsupported`, `disk`, `unavailable` and `app`. VOD covers provider movies, episodes and downloaded copies; catch-up of a live channel is `live`. There is no provider, source type, title, channel, content or stream identifier.

### Not sent

- `recording_started`: the app cannot record. "Recording" in its source means a provider's catch-up archive, which plays as a `live` run, and Downloads are reported by `download_ended`. Neither is relabelled as recording.
- A search result count: `search_used` is queued at the first nonempty query of an episode, before any of its result sources has answered. No search text is ever sent.
- Per-request open outcomes and renderer start counts from the daily summaries. Stream events replace the former; use `app_active_day` as context for `renderer_exited`, which has no per-launch denominator.

## Desktop summaries from 0.0.16

`usage_window` has `window_start`, `window_end` and sparse `counts`. UTC windows last five minutes. Keys are exactly `action_` plus one of the nine action literals, `feature_` plus one of the ten feature literals, or `setting_` plus one of the nine setting literals above and below. Absent keys mean zero. Values are positive safe integers. No arbitrary key or preference value can enter the map. Counts are disjoint delta fragments, never cumulative snapshots. Every admitted burst is saved through the existing atomic serializer; five minutes delays transmission, not durability. Quit, UTC-window and update-channel boundaries seal immutable UUID fragments. The committed update-channel change counts in the new channel. A restart seals retained counts at their original bucket timestamp. No empty fragment is sent. Ordered action trails and exact action timestamps are no longer available.

`stream_summary` has `stream_type`, `started_at`, `started_update_channel`, `watch_duration_seconds` and `end_reason`, either `ended` or `interrupted`. Only a run admitted at its own first eligible confirmed play owns a summary. No start event or periodic server heartbeat is sent. Every ordinary terminal stop sends `ended`, including replacement, local renderer loss and quit. Continuations adopted after consent reset, or already marked started, own no summary. Failed opens send their one direct incident and no summary. Terminal build/channel dimensions describe the end. Playback charts use the completion or last saved recovery observation day/channel; original start time/channel remain available for detailed analysis.

One unfinished interrupted summary with a future UUID and accrued milliseconds is journaled at first admitted play, each five minutes of additional counted progress, and explicit pause/stop with additional watch time, suspend, output and run transitions. Waiting, seeking, paused scrubbing without added watch time and per-second lease renewals do not write; they still update counted time in memory. Normal end atomically retires the journal into the immutable outbox. Startup recovery is the first serialized task after base loading, so reading consent does not wait on its write. Recovery uses the last saved timestamp, original envelope and UUID without time while dead. Interrupted duration is a lower bound that can lose up to five minutes plus the state lease. No later launch means no recovered report. Interrupted duration is separate from completed averages.

Usage admission, first-play summary admission and direct reliability each have independent saturating 60-per-minute budgets. Finalization never checks admission again. First/day observations remain outside those budgets. Pending direct events, sealed summaries, the open usage window and the unfinished play share 64 slots and a 128 KiB record budget. Each occupied open item reserves one of those slots. Oldest queued summaries are discarded first, then oldest direct work other than the first installation observation. Active counters have only 28 keys and the journal has one run. Saturation, byte/count overflow, expiry and unfinished unflushed work can lose data and bias reliability reports.

Summary work expires after seven days. Only a conclusively pre-body DNS/connect/TLS failure refunds its reserved delivery attempt. Any possible transmission, timeout after body or retryable HTTP response consumes one of three total attempts. Retries use the identical event UUID, timestamp and body with exponential backoff from two seconds capped at five minutes, or resume at launch after their persisted due time. Three ambiguous/retryable deliveries exhaust the budget; terminal 4xx discard. Ready direct events drain before ready summaries, and summary backoff cannot hold an incident. Direct events retain the bounded three-attempt policy. UUID reconciliation is required; HTTP delivery is not exactly once and production ingestion deduplication remains a rollout check.

The serializer still fails closed after 1.5 seconds; collection becomes unavailable for the session without inventing a new identity or resetting enabled consent. Quit waits at most 500 ms total. Opt-out synchronously clears incoming counters/journal/work, aborts the owned request, and serially clears all persisted work. Consent generations reject stale callbacks. Re-enable never backfills.

## Playback runs

Gameplay admission never awaits a separate analytics reply. Live/VOD/copy opens, receiver preparation/loads and existing-session replay carry an ephemeral control hint. Main validates the current trusted frame, order and actual playback kind, mints its own run/binding UUIDs, and resolves facts only against the current control and binding. Controls, frames and bindings stay in bounded memory and never enter persisted state or capture. A delayed, rejected or absent measurement reply cannot delay opening media. Repeated current hints keep one run; an explicit replay gets a fresh hint; superseded or ended hints cannot restart an old run.

In 0.0.15, `stream_started` marks the first confirmed eligible playing interval. From desktop 0.0.16 this same observation admits the future summary without sending it. Resolving an open, loading a receiver or holding a VOD first picture paused does not count. Local engines report unpaused clock progress; receiver state comes from the main Output service after its load-generation guard, which establishes receiver-confirmed playing, not audible sound or a displayed picture. Automatic Home/guide previews mint no run. Promoting a playing preview to Watch starts the run then; returning to preview suspends measurement and returning to Watch keeps the same run. Intentional mute in Watch and the mini player remain eligible.

Reconnects, quality/audio/track changes, seeks and output moves keep the run. A new run ends the previous one: another channel, title, copy, explicit replay or the next episode. Explicit stop, renderer termination or reload of a local run and quit also end it. On a receiver, main Output ends the run itself when the viewer stops it, the receiver stops it without a stream failure, a title plays to its end or its subscription goes, whether or not a window is open. Reloading for tracks or position, a broken stream awaiting retry, a lost or released receiver and moving output only end that load's observation, never the run. Renderer loss leaves genuinely continuing receiver playback under main ownership; adopting it in a new window keeps its run. A title stopped on the receiver and played on from the app is a new run.

`watch_duration_seconds` is main's monotonic elapsed time while the current binding reported eligible `playing`, rounded once to whole seconds. It never uses title positions, playback speed, receiver interpolation or engine played-time totals, so one minute at 2x speed is 60 seconds. Pause, buffering, seeking, replacement/recovery gaps, preview and suspend add nothing. Engines renew state every second; local state expires after five seconds and receiver state after fifteen unless the authoritative producer confirms it again, which bounds a stalled producer's error. These durations do not establish viewer attention.

From desktop 0.0.16, the existing `stream_error` can also contain these optional properties. This adds no event, changes no coarse `error_type`, and does not change iOS capture. Desktop 0.0.15 and historical events lack this context and must be treated as unknown.

| `diagnostic_reason`      | `tool_missing`, `tool_failed`, `probe_failed`, `malformed_input`, `unsupported_input`, `decode_rejected`, `copy_rejected`, `conversion_failed`, `inspection_undetermined`, `hls_subset_unsupported`, `network`, `provider_refused`, `provider_unavailable`, `unknown` |

These are facts available at the reporting boundary, not the media's identity. Container describes the inspected input in main, or the delivered format when only the renderer knows it. Delivery says whether a known plan converts any picture or sound; fallback identifies the compatibility step, not an attempt number. Codec families come only from typed inspection/probe facts. An unresolved conservative inspection guess stays unknown. No message, stderr, path, URL, provider, login, content identifier or arbitrary codec name is collected. Decode rejection does not establish that a decoder is missing. Unknown or absent context never establishes a codec cause.

Capture and IPC validation reject unknown diagnostic literals. On disk, future optional diagnostic values are omitted independently, retaining valid consent, identity and legacy queued events. The actual 0.0.15 loader deletes these additive properties and preserves the old event and all its existing enum values. No new event name enters the legacy queue in D1.

A run that never confirmed playing sends neither playback boundaries nor a summary. `stream_error` needs no start: a failed open, after internal format/repair fallback, sends one error and nothing else. Repeated attempts within an incident do not send again; confirmed recovery closes it, so a later break sends again. Public open failures, engine classification and receiver loads share the incident guard. Supersession, explicit stop, pause, preview refusal and shutdown are not errors. A receiver title's load that fails before Output creates its physical observer reports for the current run; afterwards Output owns load and adapter failures.

The `setting_key` rows are `settings_changed`. Preference comparisons happen inside Settings' file serializer and notifications follow successful persistence. Update channel and dismissal observations belong to Updates; source and refresh observations to their committed operations; favourites to the viewing transaction. These are preference-change events, not a claim that every change came from the Settings screen. Volume/mute, consent, TMDB keys, provider/guide configuration, credentials, last channel/category and title/variant choices are excluded.

Classification reads typed failure kinds and bounded HTTP status categories only to select a code. It never copies an exception, message, status number, log, stack, URL, path, title, channel, provider or search query. A refused stream with HTTP 401/403 maps to `credentials`; other refusals and unavailable/provider-error streams to `unavailable`. Download folder/full-disk failures map to `disk`. Feed offline failures map to `network`, invalid feeds to `app`, HTTP/rate-limit failures to `unavailable`; unknown app failures map to `app`.

## Consent and bounds

Opt-out pauses collection synchronously before queued disk writes, aborts the owned request and clears unsent and pending events. The current playback run is dropped without a `stream_stopped`. Restart stays off. Re-enable sends nothing about the disabled period: a run continuing across it sends no start, no stop and no historical duration, and transactions or operations that began while disabled, or before an opt-out, report nothing. Opt-out keeps the installation identity and first-seen/day ledger. Update-channel changes do not end runs; each event carries the channel current when it was queued.

Unconfigured builds send nothing. Development, automated and isolated profiles cannot use production capture. An isolated local verifier can explicitly select a literal loopback endpoint; it cannot fall back to production or follow redirects there.

Events need the installation identity, which the first foreground observation creates; anything earlier is dropped. New direct captures are limited to 60 per minute and the excess is dropped; first-seen/day observations, queued events and retries are outside that limit. A burst coalesces into one serialized outbox write, so playback, transfers and the UI never wait for disk or network, and playback time accrues in memory without per-second writes. Desktop 0.0.15 keeps at most 64 queued events and sends each straight away with three attempts in all. From desktop 0.0.16, the summary and shared-work limits above apply; direct events still send promptly under the same attempt limit. An exhausted reservation left by interruption is retired at startup without a fourth attempt, including the installation observation. That observation is protected against overflow while it remains deliverable. Quit seals usage and finalizes the current admitted play before draining due work, preserving retry backoffs and the 500 ms total wait. Unflushed work, admission limits, overflow, expiry and exhausted delivery attempts reduce coverage.

## iOS app

The iOS app (`apps/ios/src/telemetry/`) has its own owner with the same event names, literals and bounds wherever it has the same observation. It is on by default: Settings' Privacy section has the switch, Share basic usage statistics, which saves the choice at once and keeps it across launches, an earlier off included. With it off, or in a build without a capture configuration, nothing is recorded or sent; Settings says when a build sends nothing or only to a local endpoint.

Every iOS event's properties are `app_version` (app.json's version), `app_build` (the binary's `CFBundleVersion`), `os: "ios"`, `os_major` (iOS's major version, when readable), `$process_person_profile: false` and `$geoip_disable: true`. There is no `arch`, `build_channel`, `update_channel`, `distribution` or `profile_origin`, and no device model, locale or other device detail. Filter app reports by `os` to keep iOS and desktop apart; `app_version` alone matches both.

## Persisted legacy state

Format-one `analytics.json` files held daily summaries. Loading one discards its current/ready counts and any queued `app_summary_day`, which are never sent, and immediately writes format two. Consent, identity, origin, the first-seen/day ledger and other queued events keep their UUID, timestamp and attempt count. Unknown keys are deleted and invalid known values fail closed without logging raw values.

Desktop format 2 remains the actual 0.0.15 base schema. Every old event name, including retired action and playback producers, stays in a consumer-only validated legacy load/send union. Only legacy events enter `pending`. New events belong exclusively in optional `summaries`, version 1, with its own installation ID, pending summaries, active usage and unfinished journal. Optional work is validated separately. Unknown versions, invalid values, wrong identity or malformed window metadata discard the optional block without losing valid base consent, identity or the legacy queue. Expiry applies per item: old pending entries are removed and an old open window or unfinished play is cleared independently, preserving fresh peers. Invalid base state still fails closed without raw logging.

The actual 0.0.15 loader ignores this optional block, deletes additive diagnostic fields and preserves consent/identity/legacy capture. Its next ordinary write removes unsupported summary work. An old-build opt-out clears work and cannot revive it on re-upgrade; re-enable keeps identity and does not backfill. A no-write return may recover retained supported work only within seven days and matching enabled identity. Never add a new name or new old-enum literal to legacy `pending`; future event families need a separately versioned optional block.

## Compatible dashboard definitions from desktop 0.0.16

Group by recorded `app_version`, `build_channel`, `update_channel`, `os`, `arch` and `distribution`. Deduplicate by event UUID.

- Action totals: legacy direct matching events weighted one, plus sums of the matching usage counter across all fragments.
- Adoption: union legacy matching installations and positive matching usage counters, then distinct installations over the entire period. Never add two unique-installation series or daily distinct counts.
- Reported plays: native Trends counts legacy `stream_started` and normal/recovered `stream_summary` at each event's reporting timestamp in Europe/Brussels. Legacy starts retain their recorded day. New summaries count on completion or the last saved recovery observation day, using that reporting envelope's channel. A play crossing midnight moves to its completion day; a recovered report uses its last saved observation, not restart time. Totals remain one admitted report per logical play. Label this change explicitly and retain `started_at` and `started_update_channel` for optional detailed start-cohort analysis. Counts stay provisional while runs have not ended or returned after interruption.
- Completed watch time: legacy `stream_stopped` duration sums/counts plus `stream_summary` with `end_reason = ended` duration sums/counts. Divide combined sums by combined counts, never average averages. Terminal timestamps own this duration. Keep recovered interruption duration/count separate.
- Playback errors: unchanged `stream_error` by `error_type`. Errors per reported play is an incident frequency, can exceed 100%, and is provisional for partial periods because summaries arrive later.
- Download and update-check reliability: unchanged `success / (success + failed)` over direct outcomes, with the denominator shown and `interrupted` separate.
- Renderer exits: direct `renderer_exited` by `reason`, beside active installations.
